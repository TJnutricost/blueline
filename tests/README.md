# Blueline tests

Headless Chrome regression tests for element selection and the annotation tools.

## Run

```bash
cd tests
npm test
```

No `npm install` step is needed. The suite has no npm dependencies: it drives your installed Chrome through a small DevTools-protocol client (`cdp.mjs`) built on Node's built-in WebSocket.

`npm test` runs the Product Library unit tests (`library.test.mjs`), the Product Mapping unit tests (`mapping.test.mjs`) and then the browser tests; it exits non-zero if any check fails. `npm run test:library` runs only the unit tests. To test another copy of the extension, for example `main` checked out elsewhere, run `node run.mjs <extension-dir>`.

## Requirements

- Node.js 22 or newer (for the built-in WebSocket).
- No npm dependencies.
- Google Chrome or Chromium. The runner looks in the usual macOS, Linux and Windows locations. Set `CHROME_PATH` if yours is elsewhere.
- No network access. All fixtures are local files in `fixtures/`. `css-rules.html` is served by a small built-in `node:http` server on 127.0.0.1 (so linked and `@import`-ed stylesheets can be read); the same server reached as `localhost` acts as a cross-origin stylesheet.

## Limits

- **Not a real extension load.** The scripts run in the page's main world, not Chrome's isolated content-script world, and `background.js` (capture, downloads, the Product Library's cross-origin store fetch) is not exercised. The Product Library tests use a same-origin fake storefront, never the real Shopify.
- **Real-Chrome checks are still needed.** Keyboard shortcuts, screenshots and exports must still be checked by hand.
- **Optional live sweep.** `npm run sweep -- <url> …` compares Blueline's point targeting with the browser's raw hit target on live pages. It needs network access, results change as sites change, and it is not part of `npm test`.
