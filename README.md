# Blueline v0.7

Point at things on a webpage, try changes live, say what should change, and export a concise **Change Report** for a developer or an AI assistant. No account, API key or subscription needed.

## Install
Blueline is a Chrome extension loaded from a folder ("unpacked").

1. Get the Blueline folder (or extract the ZIP to a permanent place such as `Documents/Blueline`).
2. Open `chrome://extensions` and turn on **Developer mode**.
3. Click **Load unpacked** and choose the folder that contains `manifest.json`.
4. Optional: pin Blueline from the puzzle-piece menu, and set a shortcut at `chrome://extensions/shortcuts` (the default is Alt+Shift+Q).
5. Reload any tabs that were already open, then press the shortcut or the toolbar icon.

Keep the folder: Chrome reads it every time it starts. **To update**, replace the files in the same folder (or `git pull`), click reload on the Blueline card, and reload your tabs. Saved notes and your shortcut carry over.

## How it works
1. **Select** what the note is about: **Select element**, **Select area**, or just Shift-click / Shift-drag on the page.
2. **Edit** (optional): try the change live with the Toolbox, Edit CSS, Annotate or Align.
3. **Describe** what should change. The box tells you whether Blueline has recorded any changes yet; with none, a description is required.
4. **Save note.** When you have all your notes, press **Export Change Report** and share the result.

## Selecting
| Action | What it does |
|---|---|
| **Select element** (Alt+P) | Click an element. (Dragging around it works too.) |
| **Select area** | Drag a rectangle over one element, several, or an empty spot ("add something here"). |
| **Shift-click** | Add an element to the note, or remove a selected one. With no note open it starts one. |
| **Shift-drag** | Add everything inside the rectangle. Esc cancels it. |
| **+ Add another element** | Keep clicking to add more, then press Done. |
| **✕ on an element** | Remove just that element and its edits from the note (Undo brings it back). |
| *(no target)* | Save a general note about the whole page. |

Esc cancels the active tool. ⌘Z / Ctrl+Z (or ↶) undoes your last change in the open note; after saving it reopens the last note so you can keep or cancel the undo.

## Editing a note
With several elements selected, choose which one you are editing; each keeps its own edits.

| Tool | What it does |
|---|---|
| **Toolbox** | Edit text, Move, Measure, Match style, Hide, Sample color. Changes preview live on the page. Its actions start collapsed; press Toolbox to open or close them. |
| **Edit CSS** | Pick one of the CSS rules that match the element (or **This element only**). It lists that rule's own properties as written; **+ Add CSS property** adds others. Values preview on that element only. Border, margin, padding, border radius, box shadow and linear gradients also get separate fields under a **Fields** button (one section open at a time; required ones marked *); raw CSS always stays editable, and Enter in a value input applies it and leaves the field without saving the note. |
| **Annotate** | Arrow, box, circle, pen, text. They appear in the note's marked-up screenshot. |
| **Align** | Line an element up with guide lines, or with another element you click: **Align edges**, or **Place next to** (outside it, with Center and Middle options). Several elements move as one group. |
| **Apply CSS changes to** | Just this one, everything like it inside a container, or everywhere. The preview always stays on the one element. |
| **Changes** | What you changed on this element. ✕ reverts one change. |

Describe also has **Screen size** (which sizes the change is for; it doesn't resize the page), **Broken / error**, and a per-note Figma link (the microphone button dictates the note). An optional **Product card** section finds the product card around the element you selected (by structure, not by tag or class name), outlines it, and lets you step to its **Parent** or back down to a **Child** before you **Confirm card**; your own selection stays as it is and you can still annotate a price or title on its own. A confirmed card is saved with the note and re-checked whenever it is reopened or exported (**Check card** does it on demand): if the page changed so that Blueline can't be sure which card it was, it says so (**Needs confirmation**, **Can't tell which card**, **Not found**, **Hidden**) and never moves the note to another card without you choosing it. The parts Blueline found in the card are under **Detected fields (n)**; pressing one shows it on the page (nothing is assigned yet).

**Choose Product** (first in the section, once a card is confirmed) opens the Product Library window in selection mode: switch saved lists, search by name or SKU, review the product (image, SKU, exact variant id, prices, approval) and, on a Shopify list, pick the exact variant (a product with a single variant says so). Its confirming button stays visible, and you return to the same note. Choosing reads the Library; it never changes it. Shopify is optional; manual products work without it. A variant whose **SKU differs** from the one the list approved is a replacement: the final button is a green **Approve Replacement**, which approves it for this card only (the list is not touched). The replacement starts with the new variant's own title and image, no approved regular price and no sale price (nothing is carried over from the earlier SKU), and any page-specific values you had set must each be kept or dropped before it can be approved. The mapped product is a compact summary with **Change Product**, **Change Variant**, **Check Shopify** (a read-only look at the exact variant in the store) and **Remove Mapping** (asks first; keeps the card, text and CSS). **Edit card values** opens the title, image, regular and promotional price and product link for this card on this page only; the Library, the imported file and the variant are never changed, and a displayed price does not change Shopify checkout. A mapping keeps its own list (by id, so it can come from any saved list) and is compared with that list record whenever it is reopened or exported: only a real change to that record is reported (with the exact difference), never applied silently, and **Use the list’s current values** adopts it on purpose. Choosing another variant is never reported as a change. A confirmed card that has a mapping shows a small **Mapped** marker on the page (amber when something needs attention); clicking it reopens the note. A mapping on its own is enough to save a note.

## The Change Report
The export is a short, change-focused report: the page and detected technology, then for each note its type, your text, the target element and selector, the CSS rule and property changes (old → new), scope, alignment and measurements, drawings, and screenshots. Bugs also include diagnostic details and the steps before the note. Reference-only items (measurements, sampled colors) are labelled as such. **Source page vs implementation target.** The report names the page Blueline inspected in Chrome (a URL or local file path) once, as a **reference only**, and tells the coding tool to find the matching files in its own open project, match their structure to the inspected page, ask when several files could be the target, and never edit the inspected file, QA fixtures or original documents. Headings carry only the page's file name. **Product mappings** export field by field: for each card the title, image, sale and regular price, discount badge, call-to-action and link, each with a selector relative to the card, the value that goes there and a status: **confirmed** (you assigned it in Product Mapping), **detected** (found by Blueline when the report is built, never described as confirmed), **ambiguous**, **not identified** or **needs review**. Generic or positional selectors are marked fragile and come with the element's markup and parent. Fields are re-read from the page when you export from that page; on other pages only confirmed assignments are listed. The displayed price is stated explicitly (a card with one price shows the sale price; two prices show the sale price and the struck-through regular price; no sale price shows the regular price) and is a display value that never changes what checkout charges. Existing category labels such as “PROTEIN” are listed and flagged when they don't fit the assigned product. In the export window, **Include Add to Cart implementation** (off by default, not saved) switches the cart section from “not requested” to platform-neutral instructions to implement working Add to Cart with each card's exact variant id, including Shopify theme guidance, and to report blockers instead of faking it.

Opening, copying (**Copy Report**) or saving the report never downloads anything; press **Export Screenshots** to download the screenshots, which then adds their file paths to the report.

## More tools
Guide lines, a design-image overlay, **Check prices from a CSV** (Shopify pages, read-only), and **Hide / Show my live edits**. Saved notes stay on the page as numbered badges; **Show / Hide outlines** (off by default) adds a thin outline around the elements of saved notes. While you edit a note, its element is always outlined.

## Import Product List (optional)
**More tools → Import Product List** keeps a standalone list of products (a campaign list, a launch list, any product spreadsheet). Once a list is uploaded it appears as the **Product Library**. **No Shopify store is needed** to upload, view, edit, approve, save or export a list; a store is optional and only used to verify products afterwards. Blueline works the same without any of this.

1. **Upload File** (CSV, JSON or DOCX) or drop a file onto the window. The list is named after the file; its name is plain text with a small pencil beside it, and the pencil opens a Save / Cancel rename (only a saved, changed name edits the list). The file is only read, never changed. The screen shows one line, **Original imported file: <name>**; its size, import time and full SHA-256 are under that line's **Details**.
2. Importing another file into a list that already has products asks how: **Create a new list** (default), **Add products to the current list**, or **Replace** the current list's imported content (needs a second click; earlier imports are kept, and your corrections stay with products that are still listed). Nothing is merged or overwritten silently.
3. Products show a neutral **Not verified** until checked. Optionally enter a **Shopify store**, press **Set Store**, then **Check in Shopify**: it finds each SKU's exact variant (read-only: public `/search/suggest.json`, `/products/<handle>.js` and `/cart.js` only) and never picks one for you when several fit. Searching the store as you type waits for a pause, needs three characters and sends one request at a time.
4. Each product is a compact card: a small image, the name, the selected options (flavor, size…), the approved or working price, **one** status (**Verified**, **Not verified**, **Needs review**, **Replacement approval required** or **Replacement approved**), what needs doing, and **Edit Information**, **Change Variant** and **Details**. Anything that needs your decision is on the card: the price approvals while a price is unresolved, and a green **Approve Replacement** for a variant with a **different SKU**. That card stays amber, with the original and the proposed replacement shown apart (the replacement tinted green and labelled "not approved yet"), until you approve it, even when the price matches. Then it shows "Replacement approved".
   **Details** opens in place and shows each fact once: when the imported, Shopify and approved name, SKU and regular price agree, the value appears a single time with a ✓ mark; only differences (a different SKU, a price mismatch, a manual override) get separate, flagged lines. It also has the **variant ID**, product ID, handle and URL (each with a copy button), the promotional price, availability, verification, source placements and the less common actions (Refresh, Clear approval, Revoke approval, Find different product…, Remove). **Full source comparison** opens a table (Field | Imported SMP | Shopify | Approved / Current) of every source value, with differing cells highlighted. Prices differing by exactly 1¢ are flagged as rounding, never silently changed.
5. The header shows the unique product and source placement counts. **All**, **Needs review** and **Promo price warnings** chips filter the list (click an active chip again to show All). A promo price that doesn't match the stated discount is its own warning, not an original-price mismatch.
6. Fix a price with **Use Shopify price**, **Accept SMP price** or **Custom price…**. **Edit Information** changes the display title, regular and promotional price and image (and the SKU of products you added by hand), shows original, Shopify and edited values side by side, and has a Reset for each. Edits never change the imported file or the Shopify link.
7. **Change Variant** replaces the library with its own view inside the same window (← back, the product name, "Current: …"). Pick one variant from a radio list (options, SKU, price, availability, a Current marker, the variant ID in small type), then **Review Variant Change**, which is only enabled for a different variant. The review shows Current and New side by side; a different SKU is called out and needs its own replacement approval. **Confirm Variant Change** applies it and returns you to the same place in the list with the product highlighted; Back or Esc changes nothing. **Find different product…** (in Details, or at the bottom of the view) is for a wrong product. **+ Add Shopify product** and **+ Add product by hand** add products that weren't in the file.
8. **Export Full List** saves every product (unresolved and non-Shopify ones included); **Export Approved Products** saves the approved ones with verification details and lists the rest with a reason. Exports (`blueline.product-library/2`) keep the imported `sku`/`name` apart from the selected `shopifySku`/`variantId`, and say whether an identity is exact or a substitution.

**Manage lists** (a small link under the list name) opens the List Manager as its own view inside the window (← Back, New List), replacing the library until you go back: every saved list with its name, **Created** and **Last edited** date and time, store, product and review counts, and badges for your corrections, replacements to approve or approved, **Same source file** (same file hash) and **First imported** (saved earliest of those; it doesn't mean it is the most correct). Only real changes update Last edited: opening a list, searching, expanding Details or browsing don't. Nothing is merged or deleted for you. The order is fixed by creation time. New List, Open, Rename and Delete are on each entry; Delete first shows what the list holds that exists nowhere else.

Button colours mean the same everywhere in the library: **blue** is the step that moves you forward (Upload File on the empty screen, Review / Confirm Variant Change, Save Changes, Add product, New List, Save name), **green** approves (Approve Replacement, the price approvals), **red** confirms something destructive (Delete permanently), and grey buttons are secondary (Details, Edit Information, Copy, Cancel, Back, Close).

Lists are saved under a generated id (renaming changes only the label), each with an optional store. Visible list names are unique (trimmed, case-insensitive): importing, creating or renaming into a name that is taken gives “Name (2)”, “Name (3)”, and lists that already shared a name are numbered once, oldest keeping its name, with ids, products, corrections, approvals and mappings untouched. A website or local file only reopens the list it last used; another one starts empty, and you choose a saved list or store on purpose. No credentials are used and nothing is written to the store.

## CSS conflicts
When you click **Save note** and one of its CSS changes clashes with another saved note (the same element, the same property, a different value, and a screen size both notes cover), one dialog, **CSS Conflict — Action Required**, lists every clash: the element, the property, the screen size, and the existing and new value side by side. Choose **Keep Existing** or **Use New** for each one, then **Resolve & Save**; Cancel saves nothing. The value that loses stays in its own note, marked inactive for those screen sizes. It is not previewed, and the Change Report leaves it out of both the note summaries and the detailed CSS. Nothing else in either note changes, and the choice is saved with the notes. Only identical property names are compared (`border` and `border-color` are not).

## Limits
- Live edits are previews and vanish on reload; saved notes keep them.
- Hash routes (`/#/page`) count as separate pages. No picking inside iframes.
- Cross-origin stylesheets can't be read, so their rules aren't listed.
- Edit CSS doesn't work out which rule wins the cascade, and rules under `@container` or `@scope` are marked "condition not checked".
- On React apps, use a dev server: production builds remove component names.
- Shopify features are read-only; nothing is written to the store. Product Lists assume two-decimal currencies and reads a store only if its public product endpoints are on.

## For developers
Automated tests live in `tests/` (see `tests/README.md`). Run `cd tests && npm test` (Node 22+ and Chrome).

## Product Mapping

A green **Mapped** badge on a product card opens the **Card Mapping** window (subtitled with the card's place, for example “Card 1 of 3 in Featured Deals”): change the product or variant, edit this page's title, image, prices and link, approve a different-SKU replacement, check the variant in Shopify (read-only) and save with one button (Map & Save, Replace & Save or Approve & Save Replacement). The **Product Library** button under + Add note opens your saved lists.

### Page elements (the card's title, image, prices, badge, button and link)

In the same window, **Page elements in this card** proposes which element on the card holds each part: title, image, sale price, regular price, discount badge, Add to Cart button and product link. It reads only the confirmed card (never a neighbour, the navigation or the page's banners) using, in order: an optional `data-blueline-product-field` mark, standard markup (`h1`–`h6`, `img`/`picture`, `del`/`s`/`ins`, `itemprop`, buttons and links), class and attribute names (only together with matching content), and what the content is and looks like (a price, a percentage, struck-through text, size and weight). No special markup is required.
- **Each row** shows the field, what was found, whether it is *Suggested*, *Confirmed* or *Needs review*, and why. Where two elements are about equally likely it says **Several matches** and chooses nothing; where nothing fits it says **Not found**. Nothing is invented to fill a field.
- **Correct it:** **Accept** a suggestion, or the blue **Accept N suggestions** (blue, not green: it only stages them; nothing is approved or saved); **Choose another… (N)** lists the other elements this field could be (what each one says, its tag and place, and Show / Use this one); with no other candidate it says so instead of offering an empty list; **Pick on page** (click inside the card; the window steps aside, only the card is clickable, nothing on the page is pressed, Esc cancels) or **Clear** (the field is not on this card; Undo brings the suggestion back). Suggestions are never saved until you accept them and choose Save Mapping.
- **Show** steps the window aside and outlines the element on the page; a small bar says what is shown and **Back to Card Mapping** (or Esc) returns. The page's links and buttons are not pressed meanwhile.
- **Warnings are specific.** Unsaved suggestions are just a prompt to accept or choose; parts Blueline could not match with confidence say so; “The page changed since … was saved” appears only for an element that was saved and has really changed or gone.

### Assign Products (all the page's product cards)

Three screens, each with one job: **Product Library** (import, review, approve and manage products), **Assign Products** (give Library products to several cards on the current website) and **Card Mapping** (configure one card's fields and page values).

**Define Product Card** is also a main action on **Blueline Home**, available with or without a Product Library list: it runs the same definition flow below, saves the card by itself, then lists the cards it found in Assign Products.

**Assign Products** opens from **Blueline Home** (a button under Product Library, shown once a saved list has products) or from the green button at the top of the Product Library. Both open the same workspace, and neither needs a note. Cards you defined before are listed at once; with none, **Define Product Card** is the starting action. Nothing opens or searches by itself.
- **Define Product Card.** The workspace steps aside; click any part of a product card on the page. Blueline outlines the whole card it proposes, and **Parent** / **Child** adjust the outline (a container that holds several cards needs **Confirm anyway**). **Confirm Card** saves the card immediately as its own item: no note, no description, no product, no Shopify approval. Defining a card that is already defined shows its existing state instead of making a duplicate. Right after confirming, Blueline searches for similar cards and lists them.
- **Find Similar Cards** searches again from every card you defined, so a rescan never needs a note or another definition. It only adds to the list; it never removes or replaces a saved card, and a card whose page structure changed is listed for review instead of being re-linked.
- **Auto-map products.** A button in Assign Products that fills the empty cards, in page order, with the products of the selected Product Library list, in the list's order (simple sequential assignment, not matching). A preview lists the eligible empty cards, each proposed card and product (with its exact variant ID), what was skipped and why (assigned, excluded, stale cards; products with no exact variant) and how many Library products stay unused. **Apply to Draft** only stages them; adjust with click or drag and drop, and choose **Save Assignments** to keep them. Existing assignments are never replaced.
- **Card management on every card.** Each card in Page Cards is tagged **Detected** (recognized automatically, not confirmed by you) or **Defined** (you confirmed its boundary); **Assigned** is a separate status (a product saved to it). Every card offers **Edit Card Boundary** (the whole proposed card is outlined in thick orange and follows **Parent** / **Child** immediately, with the saved boundary shown as a thin dashed blue outline until the two agree; nothing is saved until **Confirm Card**, and Cancel restores the saved boundary; the corrected boundary is saved without a note and the card becomes Defined). A defined card keeps its saved record, product and field mapping when its boundary changes; if some field assignments can't be found in the new boundary Blueline asks first and names them. **Not a card** removes a candidate at once (its outline, number and list entry) and saves the exclusion for this page, so discovery and **Find Similar Cards** don't bring it back; an **Excluded (N)** button in the Page Cards heading (shown whenever something is excluded) opens the one list of them at the top, each with **Locate** and **Restore**. Excluding a saved card asks first, naming the product that would be removed. Excluding a card that was a discovery seed keeps it standing for the cards built like it, so the others never disappear; **Restore** turns it back into a Defined card at once (no duplicate) and it survives a refresh. **Remove Card** (a red button on every card row; enabled for saved cards, disabled with an explanation for merely Detected ones) deletes one defined card and its assignment (asks first, shows the assignment, never touches the Product Library or notes; the element can be found again). It is separate from **Not a card**, which excludes a false positive until restored. **Clear All Cards** opens the page-only Start Fresh dialog with Defined product cards already chosen. Display numbers are never saved; identity is the card's own record.
- **Website filters keep working.** While Assign Products is docked, the website's own category filter buttons (plain, non-submit buttons outside the cards that declare a filter or tab state, such as `aria-pressed` or `data-cat`, and whose names don't mention cart, buy or checkout) still work; hidden cards stay in the list (flagged) with their assignments, and returning to All restores everything. Links, cart and Add to Cart buttons, form submits and everything inside a card stay blocked.
- **Cards and assignments are not notes.** A defined card or an assignment is saved as a card record that belongs to the page, not to a note. Deleting or clearing notes never deletes cards or assignments (a note that carried one hands it to a card record), and removing an assignment never touches notes. Card records are not counted, numbered or pinned as notes; their assignments still appear in the Change Report.
- **Two columns.** Left, **Product Library**: the same list switching, search, product review, exact variants and replacement rules as before, in the panel (no separate full-screen window). Right, **Page Cards**: the numbered cards grouped by section, each with a preview, the assigned product (with its exact variant ID), a status (*Not mapped*, *Assigned*, *Not saved yet*, *Replacement approval required*, *Hidden on the page*), **Locate**, a red **Remove Mapping** (when a product is assigned or staged) and Card Boundary / Not a card / Remove Card. Define Product Card is the one way to add a card (Define, Find Similar Cards and Auto-map products are the primary actions); there is no separate "add a card Blueline missed". **Locate** keeps the workspace open where it is (docked or floating; a floating one slides aside only while it covers the card), scrolls the card clear of it and outlines the whole card in lime (#A3E635) with a "Located · Card #N" label for about 1.5 s (two pulses; no pulsing under reduced motion), then returns to the normal outline. Each column scrolls on its own; the search and the selected-card context stay visible.
- **Select a card, then a product** (**Use this product**, in its own box in the Library column) to stage it; or **drag a product from the Library onto a card on the page**. Select a card by clicking anywhere inside it on the page, its number, or its row. A product can go to several cards; a green indicator on the product lists the card numbers, for example **[1] [4] [8]**, and follows every change.
- **Nothing is saved by choosing.** **Save Assignments** is the one action that saves; Cancel, ✕ and Esc discard every staged change. Variant IDs stay strings. A different-SKU replacement is never saved from here: the card's row offers **Review & approve replacement**, which opens Card Mapping with the usual **Approve & Save Replacement**. **Remove Mapping** unassigns the product from the selected card: for a saved assignment it asks first, then stages the removal (the row says *Mapping removal not saved*; **Discard change**, Cancel, ✕ and Esc bring the assignment back) and **Save Assignments** applies it. The card definition, boundary and Product Library stay and no product or variant identity is left on the card; an unsaved draft is simply cleared without a question. Product information is edited in the Product Library, and fields are mapped to a card in Card Mapping (opened from the green mapped-card badge).
- **Discovery.** Starting from one card, cards built like it (same tag, mostly the same classes, a similar structure) that hold product content are listed in document order under their section headings; a card hidden by a filter is flagged. Differently built repeated groups (a price, a title and an image or button, outside navigation, headers and footers) are offered under **Not included** until you **Include** them. Banners, navigation, price-less category tiles and footers are not cards. **Not a card** removes a false positive; **Add a card Blueline missed** uses the page picker. No special HTML attributes are needed.
- **On the page.** While Assign Products is open, every visible card is outlined all the way round and has one numbered marker (in place of the green Mapped badge): **blue** = unassigned, **green** = saved, **dashed amber** = staged and not saved, a much stronger outline for the selected card. Clicking anywhere in a card selects it (the page never gets the click). The selected card is scrolled into view.
- **Dragging.** Grab a product, drag it over the page: every card shows as a drop target and the one under the pointer (even over its title, image or button) stands out in purple. Dropping only **stages** it. Near the top or bottom edge of the free part of the page the page scrolls. Esc cancels the drag. Dropping uses the list's chosen variant (use the picker to choose another).
- **Replacing.** Putting a **different** product on a card that already has one (saved or staged) asks first in a modal centred in the browser window over a subtle backdrop (**Replace the product assigned to Card #N?**, current and new product, **Cancel**, **Confirm replacement**; Esc cancels, focus stays inside). A different SKU still needs approval: the card then says **Needs approval** with **Review & approve replacement**, which opens Card Mapping's own **Approve & Save Replacement** and returns you to Assign Products with that card selected (other staged assignments stay staged); drag and drop can't bypass it. **Locate** steps the panel aside and shows the card; **Back to Assign Products (Esc)** returns. The page's own links and buttons do nothing meanwhile. Closing restores the green Mapped badges, with no duplicate numbered pins. Numbers are for looking only: what is saved belongs to the card's identity, never to a number; if cards were reordered or removed so Blueline cannot tell which card a saved mapping belongs to, none is linked and it is listed under **Saved mappings that need review**.
- **Docking.** **Right** (default, about 680px wide), **Left**, **Bottom** or **Float**, chosen with the Dock buttons; drag the edge (or use the arrow keys on it) to resize; the mode and size are remembered in Blueline's preferences. When the panel is too narrow for two columns (under about 600px) the columns stack: **Page Cards** on top as a horizontally scrolling strip of compact numbered items (each shows its number and assignment state; clicking one selects and highlights that card on the page and shows its row), **Product Library** below with its own vertical scrolling, search and selected-card context, and dragging products onto page cards still works. At extremely small sizes it falls back to one scrolling column. Only while docked Right, Left or Bottom does it reserve room: a margin on the page's root element (the previous inline value is restored exactly when it closes), so the page reflows beside it. Float overlays the page. Every other Blueline screen only overlays the page and never changes its layout.
- Limits: no Shopify cart wiring and no change to checkout prices. A card whose note is open in the note editor is not changed from Assign Products until that note is closed.

### Start Fresh and Restore Previous Session (Blueline Home)

A secondary one-row **Workspace** area at the bottom of Home, apart from the creation buttons, holds **Start Fresh…** (red, a warning, not a Save) and, when a recovery copy exists for this page, **Restore** beside it. Home shows no recovery date; the date and what was cleared are in the Restore confirmation.

**Start Fresh** opens a confirmation (“Choose what to clear from this page. Other pages and websites will not be affected.”) that names the current page and offers three options, each with what is saved here:
- **Notes and annotations**: this page's saved notes and their CSS edits and previews. Your defined cards and assignments stay.
- **Defined product cards**: this page's card definitions. This also removes their assignments (the assignments option is ticked and locked).
- **Product assignments**: assignments and their field-level mapping data. Defined cards stay.

A summary says exactly what will be cleared, and a second, explicit step (**Yes, clear this page’s data**) is needed. Only the current page (this origin and path) is touched: other pages and websites, the Product Library, imported SMP lists, approvals and settings are never read or changed. After clearing, the note count, markers and previews update at once. If cards were cleared, Assign Products starts from **Define Product Card** and does not search by itself; if only assignments were cleared, the defined cards are listed ready for new products.

**Recovery.** Before anything is cleared, a copy of this page's saved items (and their screenshots) is stored under one key, one copy per page, replaced by the next Start Fresh on that page. **Restore** always asks first (when it was cleared and what), puts it back exactly (variant IDs stay strings) and uses the copy up. If anything on the page changed since the reset it also says what is replaced (cards and assignments made since) and what is kept (notes added since). It never restores onto another page. There is no version history.

### Reset all Blueline work

In the same **Start Fresh** dialog a separate scope, **Reset all Blueline work**, clears Blueline's saved work on **every page and website**: notes and annotations, defined product cards, product assignments, saved page changes, guides, reports, screenshots, the design overlay, the price sheet and all recovery copies. Two independent, unticked options extend it: **Also delete all Product Library lists and imported data** (every list, imported record, approval and last-used reference, for all sites) and **Also reset Blueline settings and preferences** (panel side, docking and the like, back to first-use defaults). With both ticked the extension is in a genuine first-use state. Ticking an option only updates the summary; a second, explicit confirmation is needed, and nothing in this scope can be restored.

Only keys Blueline owns in `chrome.storage.local` are removed, by exact name or prefix (`blueline:batch`, `blueline:restore`, `blueline:overlay`, `blueline:sheet`, `blueline:shot:*`; with the Library option `blueline:lib:index`, `blueline:lib:smp:*`, `blueline:lib:work:*`; with the settings option `blueline:prefs`). No global clear is used, no files are touched, and other extensions' or websites' data is never read or changed. Kept Library lists stay available without any page mappings, and nothing is rediscovered after a reset. Other open tabs keep what they already show until reloaded.
